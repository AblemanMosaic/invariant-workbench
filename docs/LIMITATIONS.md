# Claim limits and open acceptance gates

## Proof

The scalar source translator is trusted code. Its tests are not a compiler-correctness
theorem. UCM's unchanged validator, verification-condition generation, certificate
checker, CPython semantics and the host remain part of the trusted base. Mathematical
integer results do not establish C++ overflow safety, database isolation, arbitrary
Python, liveness, physical stock or multi-service correctness. Unsuccessful proof
search is UNKNOWN, not disproof. The compiled C++ probe is finite testing only.

## Lifecycle and database

The lifecycle is a bounded reference implementation. Its exploration exhausts only
the supplied alphabet and initial condition. It excludes receiving unbounded stock,
more orders, arbitrary quantities, concurrency, crashes and physical truth.

The PostgreSQL adapter is supplied but live server acceptance is NOT_RUN. Fault-driver
unit tests validate the driver's branching and request handling, not PostgreSQL's
behavior. No test fixture is presented as a server. The writer role remains trusted;
other writers and administrators are outside the controlled boundary. Actual database
schema/permissions/isolation/driver versions need pinning and live acceptance.

## Zucchini and model

The exact upstream Zucchini commit `e8595c9ae94e45c1e28a3effeb7555725c3ac741`
was exported, source-root pinned, built, and tested in a network-isolated Linux/Ninja/
Release campaign. All 267 CTest tests passed. The named Shop 2.2.0 report linked four
executions as passed, and the source root remained unchanged. This establishes bounded
compatibility with those exact bytes and dependencies; it does not promise compatibility
with later commits, prove Zucchini or the tested business rules, or validate a consuming MES
application. The same campaign has not yet been replayed with native Windows/Visual Studio.
Of the 35 supported generated report structures, 19 record successful discovery and 16
record expected discovery failure from deliberately invalid upstream examples. Parsing a
diagnostic report is not successful application behavior.

No actual AI model was run. The optional Ollama transport has mocked protocol tests.
Using 127.0.0.1 restricts this client endpoint; it does not prove that the local service
or selected model cannot relay to a remote service. Operators must choose and trust
an offline local model configuration. Requests can contain proprietary code.

## Custody, isolation and authorization

Fixture keys are intentionally reproducible public test material. They seat no real
Governor, identity or signer. A process-local anchor does not prove freshness against
an administrator. The UCM worker and external build adapter are not OS sandboxes. The
recorded Zucchini campaign supplied Bubblewrap isolation externally and hid the Windows
filesystem. Use a separate isolation boundary before running any untrusted repository.
The actual fixture campaign is not evidence of production authority for the app.

## UI and platforms

Actual Mosaic Foundry code and runtime are bound. The Obligation Board now supports
in-memory binding proposals, selection, lowering, explanations, typed refusals, and
opted-in local proof/BDD/dossier rechecks. It is not a production MES editor, and its
UI does not perform network, database, compiler, model, custody, admission, or deployment
effects. The complete Python qualification and
consolidated replay passed on Windows, but headless projections and fake native control
bindings are not an HWND witness. Native Windows GUI acceptance remains NOT_RUN. No
fallback toolkit is silently selected. Native human usability/accessibility acceptance,
external integrations, and production workflow authority remain separate from the local
Invariant Workbench candidate.

The constitutional control surface is a consumer-owned local realization. CTR results
are builder-authored courts; ESA/EVS/COP/SRSA posture is derived and defeasible;
HeadlessRunner does not establish a native window; compiled operation plans grant no
authority. The package does not invoke a native UGK runtime, claim UGK certification,
or provide kernel-level EffectAtomicity. Current effect discipline covers create-only
local evidence files, not PostgreSQL, C++ processes, devices, or multi-file crash
inseparability.

## Review and economics

An external bounded artifact review reproduced local qualification and report linkage,
but did not rebuild upstream Zucchini or perform production admission. Full independent
review, inherited UCM Tier 1 and real-host boundaries remain open. Human maintenance cost,
team adoption and economic superiority are not measured. Scripted timings describe only
the observed hosts and operations.
A full build plan, successful tests, or user approval cannot manufacture those facts.
